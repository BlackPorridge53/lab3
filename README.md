- 任务：观察栈帧 `input` (20 pts 报告)

1.main函数调用了input

2.在栈中存储调用者的rbp，之后移动rbp与rsp，分别建立input函数的栈帧基址和为之后读入的局部变了预留栈上空间；$rbp指向的的内存中保存的是调用者（main函数）的旧rbp

3.保存的0x0000000000401ad1是input的返回地址，也就是 main 中call input 后面那条指令的地址

4.main中下面这一行存入了值

```
0x0000000000401acc <+9>:     call   0x401977 <input>
```

5.**`call` 的作用是保存返回地址并跳转到被调用函数。** `main` 中 `0x401acc` 处的 `call input` 将下一条指令的地址 `0x401ad1` 压栈，使 `rsp` 减少 8，然后跳转到 `input`。**prologue（函数序言）的作用是建立当前函数的栈帧。**leave`的作用是撤销当前栈帧，恢复调用者的`rbp`。ret` 的作用是取出栈顶的返回地址，返回调用者。

- 任务：利用缓冲区漏洞执行 `./malware` (25 pts 测试 + 5 pts 报告)

首先，利用 GDB 分析 `input()` 的栈帧结构，确定局部缓冲区距离返回地址为 24 字节。随后，在 payload 中写入 `./malware` 命令字符串，使用填充字符覆盖中间的栈空间，并将返回地址修改为目标指令地址 `0x401a6b`。这样，`input()` 执行 `ret` 时便会跳转到指定位置，跳过正常的算术表达式拼接过程，利用程序已有的 `system()` 调用执行 `./malware`，从而实现实验目标。

本实验利用 `gets()` 的缓冲区溢出漏洞，修改栈中的 `index` 变量，而不直接覆盖 Canary 和返回地址。

通过反汇编分析，发现程序使用 `index` 计算数据复制的目标地址。因此，将 `index` 修改为 `0xc8`，使程序在执行复制操作时，将输入缓冲区中的 ROP 链复制到 `main()` 保存返回地址的位置。

由于复制过程没有修改 Canary，函数可以通过完整性检查并正常返回。当 `main()` 执行 `ret` 时，程序转而执行构造好的 ROP 链，设置 `rdi=4` 并跳转到 `grade_eval()`，最终输出目标字符串。

为防止这种攻击，可以调整局部变量顺序，将 `index` 放在输入缓冲区的低地址方向，并对输入长度和复制偏移进行边界检查。
